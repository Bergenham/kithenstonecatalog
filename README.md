# Maker Stone — каталог камня

Django-приложение каталога, страниц услуг, заявок и импорта изображений.
Python 3.12+, Django 5.2 LTS, PostgreSQL. На Linux запускается через Gunicorn/Nginx.

- [Подготовка к клонированию и VPS](docs/deployment.md).
- [Формат и запуск пакетного импорта](docs/catalog_import.md).
- Шаблоны сервера: `deploy/`. Проверка кандидата релиза: `scripts/check_release.py`.

Зависимости устанавливаются из `poetry.lock`: `poetry install --only main`.
Старые браузерные парсеры — отдельная группа: `poetry install --with parsers`.
Для локальной разработки задайте `DEBUG=True` в `.env`; на сервере — `False`,
реальные `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS` и новые секреты.

## Локальная конфигурация

Секреты и параметры PostgreSQL читаются из `.env` в корне репозитория.
Локальный файл уже заполнен текущими значениями и исключён из Git.
На другой машине скопируйте `.env.example` в `.env` и заполните свои значения.
Зависимости для загрузки `.env` устанавливать не требуется.

Обязательные переменные: `SECRET_KEY`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`.
`DB_HOST` и `DB_PORT` по умолчанию равны `localhost` и `5432`.
Переменные окружения процесса имеют приоритет над `.env`.
Если обязательное значение отсутствует, Django выдаст понятную ошибку запуска.

Пароли с `#`, `$` или обратными слешами удобно заключать в одинарные кавычки.
Содержимое одинарных кавычек сохраняется буквально. В двойных кавычках
поддерживаются JSON-экранирования (`\\`, `\"`, `\n` и др.). Переносы строк
внутри значений и подстановка `${VARIABLE}` не поддерживаются.
Системный `OPENAI_API_KEY`, используемый командой `classify_stone_params`,
тоже можно указать в `.env`. После изменения файла перезапустите Django.

Рабочий пароль БД и `SECRET_KEY` при переносе в `.env` не менялись.
Вынос в `.env` не удаляет старые значения из истории Git; перед публичным
деплоем замените их. Сам `.env` не добавляйте в репозиторий.
